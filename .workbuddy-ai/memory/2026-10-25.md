## Bug 排查与修复（会话删除链路为主）

基线：node 817 例全绿；python 串行跑时 `bridge/test_account_store.py` 有 1 例失败。

修复清单（均已加/改测试）：
- `chatui/advisor.js` `deleteThread`：`generation++` 使捕获的 scope 失效，`isCurrent(scope)` 必然为真 → 删掉当前会话后从不刷新（界面留着已删会话）。改用 bump 后重新 `captureScope()`。
- 同上：`fetchJson` 从不 throw，失败以 `{error}` 返回，原 `try/catch` 是死代码 → 删除失败静默。改为检查 `result.error`，先刷新再 `problem()`（否则被 `clearProblem("load")` 清掉）。
- `chatui/advisor.js` `scheduleThreadRetry`：定时重试会抢 `historySerial`，用旧失败覆盖手动重试的成功结果。改为把 serial 传进重试并在落地时校验。
- `bridge/advisor_store.py` `delete_thread`：唯一不持 `self.lock` 的写方法，共享连接（check_same_thread=False）下会并入导入线程的事务被一起提交/回滚。
- `bridge/advisor_service.py`：删除只 pop `latest_run`，旧 run 留在 `_runs`；`/events` 对已删会话 `_thread_payload(None)` → TypeError → 503。改为清掉该 thread 全部 run，`_thread_payload` 抛 `thread-unknown`。
- `chatui/app.js` `pickableMessage`：缺 `hasAnalyzableText`，纯链接/占位符消息会被自动选中，后端 `_resolve_selected_targets` 整批 400 → 「分析选中」全失败。
- `electron/api-message-insights.ts`：`normalizeAffect` 的 `break` 在 `if (label)` 外，`{tone:"无",interaction:"亲密"}` 丢掉可用标签；insights 请求补 `timeoutMs: 150_000`（其余生成路径都有，Python 侧 180s 就放弃）。
- `electron/api-guidance.ts` `resolve`：`if (direct) return direct` 让下面的冲突检查永不可达，数字 id 同时指向两个 owner 时会挂错消息。
- `bridge/api_pool.py` `lease`：`primary()` 抛错时 `index` 已选、`active` 未加 → finally 递减成负数，`close_extras` 再也不复位。
- `bridge/payload_recovery.py`：先换 key 再恢复库，恢复失败会「新 key + 旧密文」永久打不开。改为 key 先落临时文件，库恢复成功后最后 `os.replace`，失败回滚库。
